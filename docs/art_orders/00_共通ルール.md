# 作画発注の共通ルール

> Codex（作画担当）へ。このルールは、すべての発注書に共通して適用される。
> 各発注書の指示とこのルールが食い違う場合は、発注書の指示を優先する。

---

## 1. 絵の目的

納品された絵は、2 つの使い方をする。

| 使い方 | 対象 | 重視すること |
|-------|------|------------|
| **3D モデルの設計図**（Claude が Blender で作り直す） | キャラクター、てき、なかま、小物、ステージの部品 | 形と寸法が正確に読み取れること。色が hex で分かること。**丸くて単純な形**で、ローポリで再現できること |
| **そのままゲーム画面に使う**（PNG を Godot に置く） | UI、ものしりカードの挿絵、顔アイコン、タイトルの絵、からだの地図 | 指定の大きさ・透過・余白を守ること。子どもがひと目で分かること |

絵としての美しさ以上に、次のことを重視してほしい。

1. **形が正確に読み取れること**（どの角度から見てもデザインが一致している）
2. **寸法が読み取れること**（同じ縮尺、同じ基準線）
3. **色が数値で分かること**（hex 値の色見本）
4. **子ども向けであること**（丸い・やさしい・こわくない・ひと目で分かる）

---

## 2. 納品の形式

| 項目 | 指定 |
|------|------|
| 形式 | PNG（sRGB） |
| 解像度 | 設計の絵は長辺 2048px 以上。3D 変換用は `01_3D変換用の絵の条件.md`。そのまま使う絵は発注書の指定の大きさ |
| 背景 | 設計の絵は無地の明るいグレー（#E6E6E6）。**3D 変換用と「そのまま使う」絵は透過 PNG** |
| 置き場所 | `art/concepts/<波>_<アセットID>/`（例：`art/concepts/W1_hero/`） |
| ファイル名 | `<アセットID>_<内容>.png`（例：`pod_turnaround.png`、`pico_face_happy.png`）。半角の英数字と `_` だけ |
| 修正版 | 末尾に `_r2`、`_r3` を付ける。古い版は消さない |
| 説明書き | 各フォルダに `spec.md` を置く（下記 6 章） |

- **絵は画像生成機能で描く**。Blender などの 3D ソフトで作ったモデルを撮った画像、プログラムで描いた図形の画像は納品しない。3D のモデル・スクリプト・`.blend` などのファイルも納品物に入れない（3D にするのは Claude の仕事）。
- 絵の中に説明の文字を入れる場合は、キャラクターや物に重ならない余白に置く。
- 署名、透かし、実在のブランドのロゴや文字は入れない。
- 画面に出す文字は、ゲーム側で描くので、絵の中には入れない（ロゴだけは例外。`W4_01_UI.md`）。

---

## 3. 三面図（ターンアラウンド）のルール

キャラクター・小物の「設計の絵」は、次の条件で描く（3D 変換用の 1 枚 1 方向の絵は `01` を優先）。

| 項目 | 指定 |
|------|------|
| 向き | 正面、斜め前（45°）、側面（本人の右側）、背面 の 4 方向。発注書で指定がある場合はそれに従う |
| 投影 | **透視をつけない正投影**（遠近感をつけない） |
| 縮尺 | すべての向きを**同じ縮尺**で描く |
| 並べ方 | **1 枚のシートに全方向を横に並べる**。各向きの間には十分な余白を空ける |
| 基準線 | てっぺん・目の高さ・底（足もとや船底）に細い水平の基準線を引き、全方向で一致させる |
| ポーズ | 正面を向いた立ちポーズ。表情は通常 |
| 陰影 | 平らな光。強い影、逆光、ドラマチックな照明は使わない |
| 禁止 | 背景の描き込み、ぼかし、動きの残像 |

## 4. ローポリで再現できる造形のルール（このゲームの画風の土台）

- **丸い塊 1〜3 個＋目＋口**で成り立つ形にする。遠くから見てもシルエットで誰か分かること。
- 細かい凹凸や模様は、色の塗り分けで表現する。
- 主要な色は **3〜5 色＋発光色**に絞る。パステル寄りで、彩度の高い色は目印（ゴール・アイテム・敵の目）に限る。
- **目は大きく**、白目と黒目をはっきり。口は単純な線または半円。
- 体から離れて浮いている細い部品、何重にも重なった透ける布、細い鎖の束などは避ける（べん毛や触手は、**太めの数本**にする）。
- 材質（つやの有無、発光部）を `spec.md` に書く。

### 大きさの基準
ゲームの中では、ミクロごう（主人公の船）の全長を **1.4 m** として扱う。各発注書に、ミクロごうとの比で大きさを書く。

## 5. 似せてはいけないもの

このゲームは将来公開・販売する可能性がある。既存の作品に似ていると問題になるため、次の作品のキャラクター・デザインに**似せないこと**。

| 作品 | 特に避ける要素 |
|------|---------------|
| 『はたらく細胞』 | 赤い上着と帽子の赤血球の人、白い制服とナイフの白血球、血小板の子どもたち、「人間の姿をした細胞」全般 |
| 『オズモシス・ジョーンズ』『ミクロの決死圏』『インナースペース』 | 白血球の警官、潜水艦の形そのままの船 |
| 『アンパンマン』 | ばいきんまん（紫の丸い体・2 本の角・ギザギザの口）、カビルンルン |
| 『星のカービィ』『ドラゴンクエスト』のスライム、『ピクミン』 | ピンクの丸い体に赤い足、しずく型の水色の体、頭に葉の生えた小人 |
| 『Among Us』『ミニオンズ』 | カプセル型の体に大きなバイザーの宇宙服、黄色いカプセル型の体にゴーグル |
| 『ドラえもん』『ポケットモンスター』などの有名キャラクター | 青い丸い体に赤い鼻、電気ねずみ など、連想させる色と形の組み合わせ |
| 『インサイド・ヘッド』 | 感情のキャラクターの色と形 |

- 描いたあとに**自分で見比べて確認**し、似ている点があれば修正すること。
- 確認した結果を `spec.md` の「類似チェック」欄に書くこと（確認した作品と、修正した点）。
- 既存の絵や写真をなぞったり、組み合わせたりしないこと。
- 実在の医学の図解・教科書の絵も、そのまま写さないこと（体の形は参考にしてよい）。

## 6. spec.md に書くこと

各フォルダの `spec.md` には、次の項目を書く。

```markdown
# <アセット名>

## 納品物
- <ファイル名>：<内容>

## デザインの説明
（どんな考えで形と色を決めたか。3〜10 行。子どもに伝えたい性格）

## 色見本
| 部位 | hex | 材質 |
|------|-----|------|
| 体 | #xxxxxx | つやなし |
| 目 | #xxxxxx | つやあり |
| 発光部 | #xxxxxx | 発光 |

## 寸法
（全長・高さ。ミクロごう（1.4 m）との比。発注書の指定と違う場合は理由）

## 3D 化のための注意
（非対称の部分、別部品にすべきもの、動く部分、表情の変え方）

## 類似チェック
（確認した作品と、似ないように修正した点）
```

## 7. 統一感

- W1 以降は、選ばれた**アートバイブルの画風に合わせる**（線の有無、塗り方、色の決め方、丸さの度合い）。
- 同じキャラクターの絵は、すべてのファイルで顔・色・部品が一致していること。
- 「てき」は目つきと色で「いたずらっぽい」ことが分かり、「なかま」は笑顔で「やさしい」ことが分かるようにする。子どもがこわがる顔（牙・血・鋭いトゲの密集）にしない。
