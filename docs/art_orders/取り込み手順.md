# 届いた絵をゲームに入れる手順（Claude 用）

Codex の納品ブランチ `art/<波>` を取り込み、仮の見た目を本番に差しかえる。
**仮のものと同じファイル名で置きかえる**のが原則（コードの変更を最小にするため）。

---

## 1. 受け取り

```bash
git fetch origin art/<波>
git worktree add ../ibs-art origin/art/<波>      # 読むだけ。作業ブランチには art/concepts/ を取り込まない
ls ../ibs-art/art/concepts/<フォルダ>/
```

1. `spec.md` を読み、「未納品」「発注書と違う点」を控える。
2. ユーザーの確認待ちにする点（見た目の好み、こわさ、似ている作品）を `docs/dashboard.md` 2 章に書く。
3. 3D 化・組み込みに足りない絵（向きの不足、透過でない、大きさ違い、hex なし）があれば、`codex_prompts.md` 3 章で修正依頼を作り、`docs/dashboard.md` 7 章に貼れる形で置く。
4. 納品物の記録として、`art/concepts/<フォルダ>/` の **spec.md と、そのまま使う PNG だけ**を開発ブランチに取り込む（3D 変換用の大きな絵は `art/<波>` ブランチに残し、`docs/art_orders/<波>_取り込みの結果.md` にブランチとコミットを書く）。

## 2. そのまま使う絵（UI・カードの挿絵・顔アイコン）

| 納品物 | 置き場所（同じ名前にする） | 使われ方 |
|-------|------------------------|---------|
| `W4_ui/*.png` | `godot/assets/ui/<同じ名前>.png` | `ui_theme.gd` / `hud.gd` / `title.gd` / `stage_select.gd` / `touch_controls.gd` が、ファイルがあれば使い、なければ いまの描き方（コードで描く）のまま |
| `W4_cards/card_<stage>_<key>.png` | `godot/assets/ui/cards/card_<stage>_<key>.png` | `card.gd` が、ファイルがあれば 3D プレビューの代わりに表示 |
| `W1_hero/pico_face_*.png` | `godot/assets/ui/pico_face_<表情>.png` | `hud.gd` のふきだしの顔。なければコードで描いた顔 |
| `W1_hero/pilot_face_*.png`、`hana_face_*.png`、`hana_fullbody_*.png` | `godot/assets/ui/` 同名 | 物語のカード・けっか・エンディング |
| `W4_ui/bodymap_hana.png` | `godot/assets/ui/bodymap_hana.png` | `stage_select.gd`（あれば `body_map.svg` より優先） |
| `W4_ui/title_keyvisual.png`、`title_logo.png` | `godot/assets/ui/` 同名 | `title.gd` |
| `W4_ui/stage_icon_<id>.png` | `godot/assets/ui/stage_icons/<id>.png` | `stage_select.gd` の番号ボタンの絵 |

手順：コピー → `tools/run_tests.sh`（インポート込み）→ `tools/screenshot.sh title/select/card/mouth` で見た目を確認 → コミット。
9 分割の端の幅は `spec.md` の値を `ui_theme.gd` の `StyleBoxTexture` の設定に入れる。

## 3. 3D にする絵（キャラクター・小物）

`.claude/skills/model-from-art/SKILL.md` のとおり。要点：
1. 透過 PNG のアルファから外形を測り（px → m は spec の寸法から）、**丸い部品（球・カプセル・円すい・トーラス）で組む**。
2. 色は spec の hex を平らに塗る（絵を写さない）。
3. `blender/characters.py` の `build_<ID>()` を書きかえる（関数名・GLB 名・前の向き +Y・`Propeller` などの部品名は変えない）。
4. `python -m blender.characters <ID>` → `tools/screenshot.sh model:<ID>` で絵と並べて確認（4 方向）。
5. ゲームの中でも確認（`tools/screenshot.sh <stage> --play=3`）、`tools/run_tests.sh --stage=<stage>`。
6. 結果を `docs/art_orders/<波>_<ID>3D化の結果.md` に書く（使った絵、寸法、部品、残っている違い、かかった時間）。

当たり判定の大きさは `enemy.gd` / `friend.gd` の `CONFIG` の `radius`・`touch_r`。モデルの大きさを変えたら合わせる。

## 4. ステージの絵（雰囲気画・表面・部品）

1. 色の決まり（spec の hex）→ `stage_db.gd` の `fog` / `ambient` / `fog_density` と、`stages.py` のマテリアルの色。
2. 表面の画像 → `godot/assets/textures/tex_<stage>_<wall|floor>.png` に置き、`stages.py` の `tube()` / `ellipsoid_room()` で UV を付けてマテリアルに貼る（`common.material()` に `image=` を足す。未実装：最初の 1 ステージで作り、ほかに広げる）。
3. 部品 → 3 章と同じ手順で `blender/stages.py` の `build_<stage>()` の中の飾り（`NC_` 接頭辞は当たり判定なし）に置きかえる。
4. `tools/run_tests.sh --stage=<id>` と `tools/screenshot.sh <id> --play=0.5/6/15` で確認。雰囲気画と並べて `docs/art_orders/W3_<stage>取り込みの結果.md` に残す。

## 5. 記録

- `docs/dashboard.md`：3 章「絵の発注と納品」の行を更新、4 章「3D モデルの状態」を仮→本番に、7 章の出し終えた依頼文を消す。
- `docs/progress.md`：1 項目足す。
- 仮のモデルを作っていた関数は、本番に置きかえても **同じ関数名のまま**にする（差しもどしは git で）。
